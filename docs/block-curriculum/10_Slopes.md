# 上り・下り — 坂の梯子

進める順番の正本は [00](00_README.md) である。本章は **フェーズ 3** の坂である。フェーズ 2 の地形の考え方が要る段（Ts6）以外は、既知角から始められる。

## 1. 結論

坂は欠けでも凸でもない。**重力の向きが床法線とずれる。**  
先に静止（S1 相当を斜面で）、次に遅い歩行、最後に上りと下りを分ける。速さは V0。凸と欠けはまだ足さない。

PyMPC は地形 roll/pitch で **指令速度を回転** する（実装事実。[qpympc-study/03](../qpympc-study/03_User_Command_and_Reference_Generation.md)、[05](../qpympc-study/05_Foothold_Reference_and_Terrain_Adaptation.md)）。足場の xy は回転前速度を使う。標準 `roll_activated=False` で推定 roll は 0。

## 2. 理論 — 一段で足す式

水平床の S1:

\[
\sum F = mg\,\mathbf{e}_z
\]

傾斜 \(\alpha\)（上りを正とする方針）では、床座標で

\[
\sum F_{\perp} = mg\cos\alpha,\qquad
\sum F_{\parallel} \approx mg\sin\alpha
\quad\text{（静止を保つなら）}
\]

歩行中の定常上りは、平行成分を摩擦と脚配置で出し続ける。  
EqualShare（\(F_{xy}=0\)、世界 z だけ）は **坂の静止からすでに足りない**（推測。実験で確認する）。

床の傾き \(\alpha\) を出し、脚力と胴体参照がそれを読む。新しい坂専用の予測器は作らない。

## 4. 関数との対応

| 足りなくなるもの | 関数 | 中身 |
|---|---|---|
| 床が水平という前提 | 床の傾き | roll, pitch, height |
| 人の「前」がワールド x | 胴体の参照 | 速度を地形つきに回転（PyMPC と同じ考え方） |
| 着地点 xy | 着地点 | 回転**前**の速度で先送り（実装事実に合わせる） |
| 力 | 脚力を決める | 平行成分。摩擦錐の法線を床へ |
| 摩擦 | 摩擦の不等式 | 法線 = 床。\(\mu\) が効く |
| 高さ参照 | `HeightRef` | ワールド z ではなく床からの高さ |

`GrfMpc` のモデルが世界 z 重力のままなら、斜面では参照と摩擦を合わせても限界がある。その確認が Ts4 である。モデル重力を床に合わせるかは、その後の改善であり、Ts1 でやらない。

## 5. 実装事実 — 教材の坂

ワークショップは `bumpy_flat` / `bumpy_uphill` / `bumpy_downhill` を持つ。名前のとおり **凸と坂が最初から混ざっている。**  
学習の Ts4/Ts5 は、できれば **滑らかな斜面** を先に置く。bumpy_uphill は X 段（[11](11_Difficulty_Map.md)）である。
