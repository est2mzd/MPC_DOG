# フェーズ 0 の現象 — 静止からごく遅い前進

進める順番の正本は [00](00_README.md) である。本章は **フェーズ 0**（両リポに共通する式）の現象と完了条件だけを書く。

予測最適化・WBC・状態推定・着地点の先送り・地形推定は、ここには出さない。それらはフェーズ 1 と 2 である。

番号 S0–S4 はフェーズ 0 の中の現象 ID である。全体の段階番号ではない。

## 1. 結論

各段は **シナリオ** と **生きている実装** と **完了の見方** で決める。  
同じ1周期の呼び出し（[00](00_README.md) §3.1）の上に乗る。

## 2. S0 — プラントが動く

**現象:** トルクを出すと関節が動く。何もしないと重力で潰れる。

**指令:** なし、または初期関節を PD で保持（任意）。

**生きる実装:** `Plant`, センサ, `clip_torque`。任意で関節 PD。

**まだ呼ばない:** 接地の意味、GRF、ゲイト、予測最適化。

**完了:** MuJoCo で Go2 が立ち姿勢の `q` から **連続 5.0 秒以上** 進む。全ステップ `qpos` が有限。制御の正しさは問わない。数値は `notebook/00` の背景。

**理解すること:** `qpos(19)`, `qvel(18)`, `tau(12)`、制御周期 dt=0.002。

## 3. S1 — 平地で静止

**現象:** 4脚が床を押し、胴体がほぼ動かない。

**理論:**

$$
c = (1,1,1,1),\qquad
F_{z,i} = \frac{mg}{4},\quad F_{x,i}=F_{y,i}=0
$$

仮想仕事の項は \(\tau_{\mathrm{map}}=-J^\top F\)。00 の運動方程式で \(\ddot q\approx 0\) のとき関節は

$$
\tau = h - J^\top F
$$

\(h\) は重力とコリオリ（MuJoCo の `qfrc_bias`）。キーフレームへ戻す関節 PD ではない。\(\tau=-J^\top F\) だけでは \(h\) が残るので、この段の静止には足りない。

**生きる実装:** 接地フラグ（定数）、`EqualShare`、`MapJT`、バイアス \(h\)、`Plant`。

**まだ呼ばない:** `PeriodicGait`、遊脚、参照速度、予測最適化、着地点の先送り、キーフレームの関節 PD。

**完了（数値。連続 5.0 秒以上、全ステップ）:**

- \(|z-z_0|<3\,\mathrm{cm}\)
- \(|\mathrm{roll}|<0.10\,\mathrm{rad}\)、\(|\mathrm{pitch}|<0.10\,\mathrm{rad}\)
- 並進速度 \(\lVert v\rVert<0.15\,\mathrm{m/s}\)
- 判定はログの連続 True 最長区間 \(\times\mathrm{d}t \ge 5.0\,\mathrm{s}\)。一瞬の通過は失敗

数字の正本は `notebook/02` の背景。満たすまで S2 へ進まない。

**理解すること:** 体重は力の和である。トルクは足先力の写像である。予測最適化はまだ出てこない。

**実装事実:** PyMPC の入力コスト参照も、立脚数 \(n_s\) に対して \(F_z^{ref}=mg/n_s\) である。S1 はその参照を **最適解ではなくそのまま指令** にする段階である。

## 4. S2 — 静止のまま重心高を変える

**現象:** 足は床についたまま、胴体 z がゆっくり変わる。前進はゼロ。

**2通りある（方針: 先に A、理解できてから B）。**

| | A 運動学 | B 力 |
|---|---|---|
| 何を変えるか | 目標関節（しゃがむ） | 目標 CoM 高さ。力はまだ EqualShare |
| 新しい実装 | 関節の補間 | `HeightRef`。下位は S1 のまま |
| 分かることは | 高さと脚の折れ | 「高さは S1 の力だけでは追えない」 |

**重要な方針:** B で高さがうまく追えないことは失敗ではなく、**予測や関節 PD が要る理由** の観察である。  
ここで予測最適化を足したくなるが、足さない。観察を書いて S3 へ進むか、S2-B に弱い高さ P 制御（\(F_z\) 全体を少し増減）だけ足す。

高さ P だけ足す場合の式（理論・最小）:

\[
\sum_i F_{z,i} = mg + k_p(z^{ref}-z)
\]

4脚で割る。まだゲイトもホライズンも無い。

**完了:**

- A: 2つの高さ（例: 公称と −3 cm）を往復し、転倒しない
- B または高さ P: 指令 z に遅れてついていくグラフが1枚ある

**まだ呼ばない:** 遊脚、予測のホライズン。

## 5. S3 — その場で足踏み

**現象:** \(v^{ref}=0\)。脚が交互に上がる。胴体はほぼその場。

**理論:** 接地はゲイト。立脚だけで体重を持つ。

\[
n_s = \sum_i c_i,\qquad
F_{z,i} =
\begin{cases}
mg/n_s & c_i=1\\
0 & c_i=0
\end{cases}
\]

遊脚は `SwingPath` で上げて下ろす。着地点は **今の足の xy のまま**（その場）。

**生きる実装:** `PeriodicGait`（trot でよい）、`SwingPath`, 直交 PD、`EqualShare`（立脚本で割る）, `MapJT`。

**まだ呼ばない:** 着地点の先送り、`UserCommand.vx`、予測最適化。

**完了:**

- 対角脚が交互に上がる（trot）
- 胴体 xy が大きく歩かない
- 転倒しない秒数が S1 より短くてよい。まずは「数歩」

**理解すること:** 遊脚中は \(J^\top F\) をその脚に足してはいけない（\(F=0\)）。足りない支持は残りの脚が持つ。これがゲイトの意味である。

## 6. S4 — 足の運びモードをそれぞれ

**現象:** 制御器は S3 のまま。変わるのはゲイトパラメータだけ。

**実装事実（PyMPC `config.py`）:**

| 名前 | `GaitType` | 既定 freq / duty |
|---|---|---|
| trot | TROT | 1.35 Hz / 0.74 |
| pace | PACE | 1.4 / 0.7 |
| crawl | BACKDIAGONALCRAWL | 0.5 / 0.8 |
| bound | BOUNDING | 1.8 / 0.65 |
| full_stance | FULL_STANCE | 2 / 0.65 |

offset が脚の組を決める。式は S3 と同じ \(\phi, d, c_i\)。

**完了:** 各モードで「その場足踏み」が1本のログになる。比較軸は **ゲイトだけ**。脚力はまだ EqualShare。

**理解すること:** トロットとペースの違いは予測最適化ではない。位相オフセットである。詳細は[06](06_Gait_Modes.md)。

`full_stance` は S1 に戻る確認に使う（方針）。足踏みが壊れたら stance に戻して切り分ける。

## 7. ごく遅い前進（着地は今の xy）

**新しい現象:** \(v_x^{ref}\) がごく小さい。足はまだ、今の水平位置へ下ろす。

**足すもの:** `UserCommand.vx`（小さい）。着地点ヒューリスティックは足さない。

**完了:** 平地トロットで、胴体がゆっくり前へずれる。数歩。まだ高速なし。まだ坂なし。速度に比例して着地点を先へ置くのは **フェーズ 2** である。

これでフェーズ 0 は終わる。次は LC（フェーズ 1）である。[00](00_README.md) §7。
