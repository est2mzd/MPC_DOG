# 一段に、新しい現象を一つだけ

進める順番の正本は [00](00_README.md) である。本章は、一段の定義だけを書く。

## 1. 結論

関数に分ける目的は再利用だけではなく、**次の実験で触る行を減らすこと** である。  
一段で「ゲイトも予測最適化も WBC も地形も」を同時に足すと、倒れた理由が分からない。

## 2. 方針 — 一段の定義

次をすべて満たすとき、それを1段とする。

1. **新しい物理または新しい決定が1つ**（例: 足が床を離れる）
2. 前の段のコードが、そのまま残って動く
3. 成功/失敗が、グラフか目視でその1つに帰着できる
4. 使わない実装は呼ばない（import もコンストラクタも）

「小さくする」はファイル行数ではなく、**同時に変わる理由の数** である。

## 3. 方針 — 足してよいもの / いけないもの

順番はフェーズに従う（[00](00_README.md) §7）。下表は現象ごとの「同時に足さない」規則である。

| この段の現象 | 足してよい | 足してはいけない（次以降） |
|---|---|---|
| ロボットが存在する | Plant、初期姿勢 | 力、ゲイト |
| 体重を支える | 4脚接地、均等 GRF、\(J^\top F\) | 遊脚、最適化 |
| 高さを変える | 高さ参照、またはゆっくりした関節目標 | 歩幅、予測最適化 |
| 足踏み | ゲイト、遊脚軌道、立脚本数で割る GRF | 前進速度、着地点の先送り |
| 運びを変える | offset / duty / freq だけ | 新しいソルバ |
| ごく遅い前進 | 小さい速度指令。着地は今の水平位置 | 高速、坂、着地点ヒューリスティック |
| LC の推定・NMPC・WBC | 関数の中身を**一つずつ** | 速さ、地形、acados を同時に |
| 着地点の先送り・短い SRBD | PyMPC 側の中身を一つずつ | LC の WBC を同時に切り替える |
| 速度を上げる | \(v\) だけ、または \(f\) だけ | 同時に地形 |
| 坂 | 床の傾き、指令を床に合わせる | 地面の欠け、高速 |
| 凸凹 | `step_height`、足先 z | 欠けの回避、高速 |
| 地面の欠け | 着地点を乗ってよい点へずらす | 同時に bound + 高速 |
| 比較 | 「脚力を決める」か「トルクにする」の中身だけ | 同時にゲイトと地形を変える |

## 4. 実装事実 — 上流は一段になっていない

Quadruped-PyMPC の標準 `run_simulation` は、初周期からゲイト・足場・acados・stance/swing を同時に回す。  
legged_control の `update` も、推定・NMPC policy・WBC・ハイブリッド指令が同時である。

上流は **完成した歩行器** である。学習階段ではない。  
同じ式を、自分の `src/` では段階的に足す。

## 5. 方針 — ループの呼び出しは最初から同じ

1周期の骨格は、静止（4脚接地）の段から変えず、中を単純な実装で埋める。形は [00](00_README.md) §3.1 である。

```text
c   = ゲイト(時間)                 # 最初は常に 1111
grf = 脚力を決める(状態, c, 参照)    # 最初は EqualShare
tau = トルクにする(ヤコビ, grf)     # 最初は MapJT
tau = 遊脚なら上書き(tau, c)       # 最初は何もしない
plant.step(トルクを飽和(tau))
```

予測最適化を足すとき、変えるのは「脚力を決める」の中身だけである。  
WBC を足すとき、変えるのは「トルクにする」の中身だけである。  
呼び出しの形を段ごとに作り直さない。

## 6. 推測 — 一段を飛ばすと起きること

| 飛ばす | よく起きる混乱 |
|---|---|
| 静止を飛ばして足踏み | 転倒が「力不足」か「遊脚 PD」か分からない |
| ゲイトを飛ばして NMPC | 接地列とコストのどちらが悪いか分からない |
| ゲイト種類を飛ばして前進 | 歩幅と位相が同時に変わる |
| 最初から WBC | \(J^\top F\) を理解せず 42 変数を見る |
| フェーズ 0 のうちに acados | 共通の力と、短い予測のどちらが効いたか分からない |
