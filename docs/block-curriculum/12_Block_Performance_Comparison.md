# 同じ関数の中身だけ変えて測る

進める順番の正本は [00](00_README.md) である。本章は比較の正本である。関数の契約は[05](05_Comparable_Planners.md)。シナリオ原子は[11](11_Difficulty_Map.md)。

## 1. 結論

性能比較の単位はシーン全体ではなく **関数の実装1つ** である。  
予測最適化は特別な実験ではなく、「脚力を決める」の比較対象である。割り算（`EqualShare`）や高さ PD も消さない。予測が無いと測れない段でも、無い側をベースラインとして残す。

比較の規則は一段一現象と同じである。**一度に差し替える実装は1つ。** シナリオ・他の関数・ログ列は固定する。

LC の NMPC（`LcNmpc`）と PyMPC の acados（`GrfMpc`）は、どちらも脚力の実装である。一つの MPC に潰さない。

## 2. 残すもの（方針）

次は比較のために捨てない。学習の入口であり、予測を足したあとのベースラインである。[00](00_README.md) §4 と同じである。

| 残すもの | 役割 |
|---|---|
| `EqualShare` | 力の最初の実装。静止・足踏みの理解 |
| `HeightPdShare` | ホライズン無しの高さ |
| `MapJT` | トルクの最初の実装 |
| `PeriodicGait` + パラメータ | 運びの比較はゲイト |
| `SwingPath` + PD | 遊脚の最初の実装 |
| 着地点 = 今の xy / 先送り | 第0・第1実装 |
| シミュレータの真値 | 推定なし |

予測や WBC を足すときはこれらを上書き廃棄しない。同じ引数で切り替える。

## 3. 比較できる関数（実装を並べられる単位）

1周期の各関数が、性能比較の1単位である。[unified-blocks/04](../unified-blocks/04_Same_Hole_Two_Laws.md) と同型（そちらの用語は「同じ入出力・別の式」）。

| 関数 | 比較する実装（例） | 予測最適化はここか |
|---|---|---|
| **脚力を決める** | `EqualShare` / `HeightPdShare` / `FxShare` / **`LcNmpc`** / **`GrfMpc`（nominal）** / sampling / lyapunov | **ここが主戦場** |
| **トルクにする** | `MapJT` / `WeightedWbc` | 違う関数。脚力と同時に切らない |
| **着地点** | 今の xy / 先送り / 地形ずらし | 違う関数 |
| **遊脚** | 生成器・PD ゲイン | 違う関数 |
| **ゲイト** | trot / pace / crawl / bound（パラメータ） | 違う関数 |
| **今の状態** | 真値 / 線形 KF | 違う関数。フェーズ 1 |
| **胴体の参照** | 定数 / 2点 / HoldVelocity | 違う関数。参照と予測モデルはセット |

1回のランで「予測も WBC も着地点も変えた」は、関数単位の比較ではない。

## 4. 予測を比較対象にする条件（方針）

`LcNmpc` も `GrfMpc` も、他と同じ土俵に乗る条件:

1. 公開戻りが `Grf (4,3)` である（内部の \(u\) を下位に直接渡さない）
2. 入力が今の状態、参照、接地スケジュール、extras である
3. 同じ `Plant`、同じ seed、同じシナリオファイルで走る
4. ログ列が `EqualShare` と同一である（[05](05_Comparable_Planners.md) §5 + 本章 §7）
5. 計算時間と solver status を **別列** で残す。追跡性能と混ぜて「総合点」にしない

PyMPC の `type=nominal|sampling|lyapunov` は、**短い SRBD 同士** の比較である（実装事実: `config.py` の切替）。  
先にフェーズ 1 で `EqualShare` vs `LcNmpc`、フェーズ 2 で `EqualShare` vs `nominal` を同じ足踏み・同じ前進で出し、そのあと MPC 同士を出す（方針）。

## 5. 比較マトリクス — どの段で何を挿すか

行はシナリオ。列は脚力の実装。● はそのランで比較してよい。— はまだその実装を主にしない。

### 5.1 脚力を決める

| シナリオ | EqualShare | HeightPd | FxShare | LcNmpc | GrfMpc nominal | sampling | lyapunov |
|---|---|---|---|---|---|---|---|
| S1 静止（フェーズ 0） | ● ベース | ○ | — | — | — | — | — |
| S1 静止（フェーズ 1–） | ● | ○ | — | ● | ●（フェーズ 2–） | — | — |
| S2 高さ | ● | ● | — | ● | ● | — | — |
| S3 足踏み | ● ベース | ○ | — | ● | ● | 後 | 後 |
| ごく遅い前進（今の xy） | ●（落ちてよい） | — | ○ | ● | ● | 後 | 後 |
| V0 以降（先送りあり） | ●（落ちてよい） | — | ○ | ○ | ● | 後 | 後 |
| V5 加速 / V7 高速 | ベースとして残す（負ける想定） | — | ● | ○ | ● | ● | ○ |
| Ts 坂 | ベース（負ける想定） | — | ○ | ○ | ● | ○ | ○ |
| Tb 凸 | ベース | — | — | ○ | ● | ○ | ○ |
| Th 欠け | 着地点が主。脚力は固定が先 | — | — | — | ずらし ON のあと | — | — |

`FxShare` は「立脚で \(mg/n_s\) + 指令加速度に比例する \(F_x\) を割る」単純実装である（方針）。予測なしだが加速では EqualShare より公平な相手になる。

sampling / lyapunov は、同じ足踏みで nominal がログとして並んでから足す。PyMPC 側の最初の比較対象は **nominal GRF-MPC** である。LC 側の最初は **LcNmpc** である。

### 5.2 他の関数（脚力は固定）

予測を見る実験では脚力を一つに固定し、次を1つだけ変える。

| シナリオ | 変えてよい関数 | 実装 |
|---|---|---|
| S3 以降（フェーズ 1–） | トルクにする | MapJT vs WeightedWbc |
| フェーズ 2 以降 | 着地点 | 今の xy vs 先送り vs ずらし |
| S3 以降 | 遊脚 | 生成器・step_height |
| S4 | ゲイト | 名前（offset 等） |
| フェーズ 1 以降 | 今の状態 | 真値 vs KF |

「予測の性能」と言いながらトルク側も変えている表は無効である。

## 6. 性能の見方（方針）

優劣を1スカラーにしない。少なくとも次の3群を分ける。

| 群 | 例 | 意味 |
|---|---|---|
| **成否** | 転倒時刻、完走、欠け落ち | 前提。ここで死んだら追跡を語らない |
| **追従** | \(\mathrm{RMSE}(v)\), \(\mathrm{RMSE}(z)\), xy ドリフト、roll/pitch RMS | 制御の仕事 |
| **コスト** | \(\mathrm{mean}\\|\tau\\|$, ピーク \(F\), 摩擦余裕、solve 時間, QP/SQP status | 代償。予測が遅いのはこの群 |

同じシナリオ・同じ群の列だけを並べる。  
「tracking は良いが 8 ms かかった」は敗北ではなく、比較結果の1行である。

数値の合格線は実験後に[02](02_Stage_Ladder.md)へ戻す。本章では列の定義だけ固定する。

### シナリオ別の主指標（方針）

| シナリオ | 主に見る追従 | 主に見るコスト |
|---|---|---|
| S1 | \(\Delta z\), \(\\|v\\|\) | \(\sum F_z - mg\) |
| S2 | \(z-z^{ref}\) | \(F_z\) 変動 |
| S3 | xy ドリフト、ピッチ | 2脚時の \(F_z\) |
| 遅い前進 / V | \(v-v^{ref}\)、走行距離 | \(F_x\)、solve 時間 |
| 坂 | ピッチ、\(v\) 沿面 | \(F_\parallel\)、\(\mu\) 余裕 |
| 凸 | 高さ外れ、転倒 | step_height との切り分けは着地点/遊脚ログ |
| 欠け | 着地点が落ちたか、完走 | ずらし量、未到達回数 |

## 7. ログに必ず足す列（予測用）

[05](05_Comparable_Planners.md) の列に加え、脚力が予測のとき:

| 列 | 意味 |
|---|---|
| `planner_id` | `equal_share` / `lc_nmpc` / `grf_mpc_nominal` / … |
| `block_swap` | 今回差し替えた関数の名前（1つ） |
| `mpc_dt_ms` | 求解時間 |
| `mpc_status` | 成功 / 失敗 / 反復 |
| `horizon_s` | ホライズン長（割り算は 0） |
| `n_stance` | \(\sum c_i\) |

これがないと「予測が遅いから転んだ」と「式が悪い」が分離できない。

## 8. 実験の命名（方針）

```text
cmp_<シナリオ>__swap-<関数>__<実装A>_vs_<実装B>
```

例:

- `cmp_s3_step__swap-grf__equalshare_vs_lcnmpc`
- `cmp_s3_step__swap-grf__equalshare_vs_grfmpc_nominal`
- `cmp_v7_5kph_flat__swap-grf__fxshare_vs_grfmpc_nominal`
- `cmp_s3_step__swap-tau__mapjt_vs_weightedwbc`（脚力は固定）
- `cmp_s3_step__swap-grf__grfmpc_nominal_vs_sampling`

ファイル名にシーンと差し替えた関数が入っていること。`cmp_final` のような名は使わない。

## 9. 公平性（再掲と追加）

実装事実: 上流は `type` で短い SRBD 同士を切るが、割り算ベースラインとの共通ループは持たない。

方針の追加:

- 重み \(Q,R\) を比較の途中で変えない。変えるならそれは別実験（`swap-weights`）であり脚力の差し替えではない
- sampling のサンプル数と nominal の SQP 反復を「同じ計算量」に揃える必要は無い。コスト群に実時間を書けばよい
- `WeightedWbc` は脚力比較に入れない（戻りが τ）。入れるなら関数名をトルク側にする
- `LcNmpc` と `GrfMpc` を同じ表の「MPC」列に混ぜない。列を分ける
- 乱数 seed と scene XML を表に書く

## 10. 理解してから測る

S1–S4 で EqualShare が何をしているか答えられないなら、予測の表は作らない（[07](07_Understand_Then_Harder.md)）。  
比較は学習のあとであり、学習の代わりではない。ただし **表の型（同じログ・関数は1つだけ変える）は S1 から用意する。** EqualShare だけのランも `planner_id=equal_share` で残す。
