# 数式・考え方で見る共通ブロック設計

## 1. 目的

上流リポジトリを **import しない**。ファイルを切り出さない。  
数式と考え方が一致していれば、**新規にクラスを設計し直してよい**。

問いは次である。

> legged_control のここと Quadruped-PyMPC のことは、こう設計すれば概ね同じブロックになるか。

このディレクトリがその分析の正本である。  
`docs/src-blocks/` は「上流ファイルをどう切るか」の別ノートであり、ここでは参照しない。

## 2. 対象の考え方（実装事実）

両方とも、人間の胴体速度指令から関節トルクまでを、次の分離で解いている。

```text
指令 → 参照 → 接地スケジュール → 予測最適（GRF） → 下位トルク → 関節 → プラント
```

違いはクラス名と状態ベクトルの並べ方である。問題の切り方は同じ族である。

理論の詳細は既存ノートへ送る。

- PyMPC の式: `docs/qpympc-study/`
- LC の式: `docs/legged_control/`

## 3. 結論（先に答える）

**概ね同じで1クラスにできる層**と、**穴は同じだが法則が2つ**の層がある。後者は無理に1式へ潰さない。Protocol（同じ入出力）の下に2実装を置く。

| 判定 | 意味 | 例 |
|---|---|---|
| **同一** | 式も役割も同じ。1クラスで足りる | 周期ゲイト、摩擦ピラミッド、\(\tau \propto J^\top F\)、指令、トルク飽和 |
| **同型** | 役割と入出力は同じ。中の式が違う | 予測モデル、NMPC、下位制御、参照の作り方、推定 |
| **片方だけ** | 相手に相当物が薄い | 線形KF、QP-WBC、足場ヒューリスティック、地形平面 |
| **合わせない** | 同じ24次元でも中身が違う。1つの状態型に無理に混ぜない | PyMPC の \(x\) と LC の \(x\) |

## 4. 記述の区別

| 区分 | 意味 |
|---|---|
| **実装事実** | 両コード／既存ノートにそう書いてある |
| **理論** | 共通の式 |
| **推測** | 「同じと見て1クラスにしてよい」という設計判断。実行検証はまだ無い |

「こう設計すれば同じ」はすべて **推測〜方針** である。コードが今日そうなっている事実ではない。
