# 無理に統一しないもの

## 1. 結論

考え方が近いことと、データ構造を1つにできることは別である。  
ここを混ぜると「ブロック化した」ように見えて、式が壊れる。

## 2. 実装事実 — 状態24を共有してはならない

| index の意味 | PyMPC \(x\) | LC \(x\) |
|---|---|---|
| 0:3 | CoM 位置 | \(m v_{com}/m\)（並進運動量の正規化） |
| 3:6 | CoM 速度 | \(L/m\) |
| 6:9 | roll pitch yaw | ベース位置 |
| 9:12 | \(\omega\) | ZYX |
| 12:24 | 足位置 | 関節角 |

同じ `np.ndarray(24,)` に両方を流すと、コストもダイナミクスも無意味になる。

**方針:** `MpcState` はモデル専用。変換が要るときは名前付き関数（`srbd_from_sensors` 等）だけが知る。

## 3. 実装事実 — 入力24も共有してはならない

| | PyMPC \(u\) | LC \(u\) |
|---|---|---|
| 0:12 | 足速度 | GRF |
| 12:24 | GRF | 関節速度 |

公開契約は `Grf` の `(4,3)` にする。24ベクトルはモデル内部。

## 4. 推測 — 「WBC」という言葉で1クラスにしない

PyMPC の `WBInterface` は QP-WBC ではない。ゲイト・足場・参照・トルクが同居している。  
LC の `WeightedWbc` は瞬間 QP である。

言葉が同じなので1クラスにしたくなる。中身は P2+P3+P4+P10+P11 である。  
新規設計では `WBInterface` 相当を作らない。

## 5. 推測 — FullCentroidal を第一ブロックにしない

LC の予測式の本体は OCS2 にあり、この workspace で未照合である。  
「LC と同じモデルブロック」を今書くと、推測の上に実装が乗る。

穴（`CentroidalModel`）だけ空ける。中身は SRBD で歩く。

## 6. 実装事実 — 足場は対称ではない

PyMPC は着地点ヒューリスティックが太い。LC は z 軌道と関節 MPC が太い。  
`FootPlacement` を必須入力にすると LC 形が書けない。optional にする。

## 7. 実装事実 — ロボットも脚順も違う

Go2 と A1 は質量も関節限界も違う。脚の呼び方も FL/FR/RL/RR と LF/LH/RF/RH。  
ブロックの核はロボット名を知らない。`extras`（質量、慣性、限界）だけを受ける。

## 8. この分析と `docs/src-blocks/` の違い

| | `src-blocks/` | このディレクトリ |
|---|---|---|
| 目線 | 上流ファイルを切って `src/` へ移す | 式が同じなら新規クラスでよい |
| import | 障害として扱う | しない前提 |
| 成功 | 上流関数との数値照合 | 同じ穴に2法則を挿せる |
| 正本 | ファイル対応 | [02](02_Pairwise_Map.md) のペア |

どちらも残す。今後のクラス設計は **こちらを先に読む**。
