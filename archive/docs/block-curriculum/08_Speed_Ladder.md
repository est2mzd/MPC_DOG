# 速さの梯子 — 遅い前進からある程度の高速へ

進める順番の正本は [00](00_README.md) である。本章は **フェーズ 3** の速さ軸である。フェーズ 2 の着地点先送りと acados が動いてから始める。

## 1. 結論

高速は新しい予測器ではない。**同じ着地点・ゲイト・脚力の関数** の上で、\(v\)、\(f\)、\(d\)、摩擦を一段ずつ動かす。  
平地に固定する。坂・地面の欠けは[09](09_Holes_and_Bumps.md)、[10](10_Slopes.md)。

理論の詳細: [qpympc-study/12](../qpympc-study/12_Speed_Frequency_Duty_and_Stride.md)。

## 2. 理論 — 一段で触る量はどれか

定常では平均推進力は小さくてよい。難しいのは脚が床に貼りついたまま胴体が前へ行くことである。

\[
L_{\mathrm{footprint}} = \frac{v}{f},\qquad
T_{\mathrm{stance}} = \frac{d}{f},\qquad
L_{\mathrm{stance}} = v\, T_{\mathrm{stance}} = \frac{v d}{f}
\]

PyMPC の足場先送りは \(L_{\mathrm{footprint}}\) ではなく \(L_{\mathrm{stance}}/2\) である（実装事実）。

\[
\Delta p_{\mathrm{ref}} = \frac{T_{\mathrm{stance}}}{2}\, v^{ref}
\]

Go2 で \(v=5\,\mathrm{m/s}\)、\(f=2\,\mathrm{Hz}\) は \(L_{\mathrm{stance}}\) がメートル級になり、可動域として非現実である（実装事実・同 12 章）。  
「ある程度の高速」はこのロボットでは **まず 1–2 m/s（およそ 4–7 kph）** を天井にする（方針。教材デモの 5 kph × 凸凹坂はフェーズ 3 の最後）。5 m/s は梯子の外である。

## 3. 段 — 速さだけ（地形は flat）

| ID | 新しい現象 | 触るブロック | 触らない |
|---|---|---|---|
| **V0** | 遅い直進。先送り ON（フェーズ 2 済み） | `vx` 小 | \(f,d\) は S3 のまま。地形 |
| **V1** | \(v\) だけ上げる | `UserCommand.vx` | \(f,d\)、地形、ゲイト種類 |
| **V2** | 歩幅が脚に合わない | 観察。\(L_{stance}\) をログ | まだ \(f\) を自動にしない |
| **V3** | 周波数を上げて歩幅を縮める | `PeriodicGait.freq` | duty、地形 |
| **V4** | duty を下げて遊脚時間を増やす | `duty` | 同時に大きな \(v\) ジャンプ |
| **V5** | 加速（\(\dot v \neq 0\)） | 脚力が \(F_x\) を出す。摩擦の不等式 | 定常高速と混ぜない |
| **V6** | 旋回しながら速く | `yaw_rate` | 地形 |
| **V7** | ある程度の高速（目安 5 kph） | V3–V5 の勝ち組 | 凸凹坂 |

各 ID で変えてよい軸は1つである。V1 で転んだら V3 に逃げる前に、同じ \(v\) で EqualShare vs GrfMpc（必要なら LcNmpc）を見る。

## 4. 実装事実 — 上流は速さ梯子になっていない

- 標準 trot は `step_freq=1.35`、`duty=0.74`。速度指令はキーボード等で連続に変わる。
- `optimize_step_freq` は標準 OFF。ON でも候補は `[1.4, 2.0, 2.4]` Hz。
- 教材デモは **5 kph × 凸凹坂** を一気に扱う。学習ではフェーズ 3 の最後である。

自分の V 段は、上流のその完成形を分解したものである。

## 5. 関数との対応（同じ文脈）

| 速くなると足りなくなるもの | 関数 | 足す中身 |
|---|---|---|
| 足が胴体の真下に残る | 着地点 | \(\Delta p \propto v T_{st}\)（フェーズ 2 で既にある。V0 で使う） |
| 脚が伸び切る | `PeriodicGait` | \(f\) を上げる（V3） |
| 遊脚が次地点へ届かない | `SwingPath` | 時間 \(T_{swing}=(1-d)/f\)。duty または \(f\) |
| 加速できない / ピッチ | 脚力を決める | 水平 GRF。EqualShare はここで死ぬ |
| 滑る | 摩擦の不等式 | \(\mu\)。予測の制約が初めて効く |
| 指令が大きすぎる | 速度の変調 | 脚が伸びたら \(v^{ref}\) を落とす。PyMPC に有（実装事実）。V の任意 |

新しい `HighSpeedController` クラスは作らない。

## 6. EqualShare が死ぬ段（方針）

V0（遅い定常）では EqualShare でも数歩は可能かもしれない（推測）。  
V5（加速）と V7（速い定常でも脚の相対運動が大きい）では、横力ゼロの割り算は足りない。  
したがって **速さの比較相手はフェーズ 2 の `GrfMpc`（と、並べるならフェーズ 1 の `LcNmpc`）** である。割り算を高速の主プランナにしない。

比較の型は[05](05_Comparable_Planners.md) の C6 のまま。シーンは `flat`。

## 7. 完了の見方（方針。数値は仮）

| 段 | 見ること |
|---|---|
| V0 | 前進距離 > 0。転倒なし |
| V1 | 指令 \(v\) に平均速度が近づく。伸び切りの有無 |
| V2 | \(L_{stance}\) と脚長の比較表が1枚 |
| V3 | 同じ \(v\) で \(f\) を上げると伸び切りが減るか |
| V5 | 0 → \(v\) のランプ。ピッチと \(F_x\) のグラフ |
| V7 | 5 kph 相当を平地 trot で数秒。地形はまだ flat |
