# 脚力の戻りを揃えて比較する

進める順番の正本は [00](00_README.md) である。比較の表と指標は [12](12_Block_Performance_Comparison.md) が正本である。本章は「脚力を決める」関数の契約と、実装の一覧である。

## 1. 結論

予測最適化を性能比較に載せるには、**割り算と同じ引数・同じ戻り** にする。戻りは `Grf (4,3)` である。  
`EqualShare` 等はベースラインとして残す。消さない。

これは方針である。上流は planner 比較用の共通ループを持たない（実装事実）。

## 2. 関数の形

```text
脚力を決める(
    x,                 # 今の重心・姿勢（その段で使う分だけ）
    flags,             # 接地 0/1
    schedule,          # 無くてもよい。予測最適化だけ使う
    ref,               # z, 速度。S1 では z のみ
) -> Grf               # (4,3)
```

戻りは必ず `Grf` である。acados の `u(24,)` や LC の `u(24)` を下位に直接渡さない。  
そうしないと `EqualShare` と予測最適化が同じ下位に繋がらない。

## 3. 比較する実装

| 名前 | いつ足すか | 中の考え方 | ホライズン |
|---|---|---|---|
| `EqualShare` | フェーズ 0（S1–） | 立脚で \(mg/n_s\)。横力0 | 0 |
| `HeightPdShare` | フェーズ 0（S2 任意） | 上に高さ PD を足して割る | 0 |
| `LcNmpc` | フェーズ 1 | LC の長いホライズン NMPC。戻りは `Grf` に落とす | 長い |
| `GrfMpc` nominal | フェーズ 2 | 短い SRBD + acados。**PyMPC 側の第一の比較対象** | 短い（例: 0.24 s） |
| `GrfMpc` sampling | フェーズ 2 の後 | JAX 標本。acados との MPC 同士 | ロールアウト |
| `GrfMpc` lyapunov | フェーズ 2 の後 | 安定制約つき | 短い |
| `FxShare` | フェーズ 3 の加速向け | EqualShare + 加速用 \(F_x\)。予測なし | 0 |
| `WeightedWbc` | フェーズ 1。**脚力比較には入れない** | 今の瞬間の \(\ddot q,F,\tau\)。戻りは τ | 0（瞬間） |

`WeightedWbc` の比較は「トルクにする」関数で行う。[12](12_Block_Performance_Comparison.md) §5.2。  
`LcNmpc` と `GrfMpc` は一つの MPC に潰さない。状態もホライズンも違う。

## 4. 比較実験の固定するもの（方針）

1回の比較で変えてよい軸は **1つ** である。

| 実験名 | 固定 | 変える |
|---|---|---|
| C1 静止 | 平地、4脚、5 s、seed | 脚力 = EqualShare / LcNmpc（フェーズ 1）。のち GrfMpc（フェーズ 2） |
| C2 高さ | 平地、4脚、z 指令の同じランプ | 同上 |
| C3 足踏み | 平地、trot、v=0、同じ freq/duty | 同上 |
| C4 ゲイト | 平地、v=0、EqualShare | trot / pace / crawl / bound |
| C5 ゲイト×予測 | 平地、v=0、脚力は一つに固定 | ゲイト種類 |
| C6 速さ | 平地、trot、同じ脚力 | \(v\) だけ（[08](08_Speed_Ladder.md)）。フェーズ 3 |
| C7 坂 | 遅い \(v\)、同じ脚力 | 上り / 下り / 0°（[10](10_Slopes.md)） |
| C8 凸 | 遅い \(v\)、平地勾配0 | 段差高さ or perlin 振幅（[09](09_Holes_and_Bumps.md)） |
| C9 地面の欠け | 遅い \(v\)、既知地図 | ずらし ON/OFF |
| C10 混ぜ | 最後 | 速さ×地形は[11](11_Difficulty_Map.md) |

シナリオ行の全表は[12](12_Block_Performance_Comparison.md) §5。本章の C1–C10 はシナリオ固定の確認用である。

フェーズ 0 では C1–C4 を EqualShare だけで走らせ、ログの型を先に作る。予測最適化の列はフェーズ 1 から足す。

## 5. 同じログ（方針）

脚力の中身が違っても列を揃える。

| 列 | 意味 | 比較で見ること |
|---|---|---|
| t | 時刻 | — |
| z | CoM 高さ | 静止・高さ実験 |
| x, y | CoM 水平 | ドリフト |
| c0..c3 | 接地指令 | ゲイトが同じか |
| Fz0..Fz3 | 指令 GRF z | 2脚時に倍になるか |
| tau_norm | \(\\|\tau\\|\) | 下位の負担 |
| Fx, Fy | 指令水平 GRF | 加速・坂・摩擦 |
| pitch, roll | 胴体角 | 坂・bound |
| p_td | 指令着地点 | 欠け・凸 |
| terrain_h | 足下高さ | 凸・坂 |
| fallen | 転倒 | 成否 |

実接触や実 GRF はあってもよいが、指令と混ぜない。PyMPC でも実 GRF は制御に戻らない（実装事実）。

## 6. 公平のための注意（推測）

- `LcNmpc` も `GrfMpc` も計算が重い。dt と「何周期に1回解くか」をログに残す。失敗が周期遅れか式かを分ける。
- `EqualShare` に摩擦制約は無い。予測側だけ転倒しない、は「横力を出せる」差であり、ソルバが偉いとは限らない。
- コスト重みをいじりながらゲイトも変えると、比較にならない。最初の重みは固定する。
- 高速で初めて EqualShare が壊れるのは正常である。水平力が恒等的に 0 だからである。C6 の比較相手は `GrfMpc`（と、必要なら加速用の単純 \(F_x\) 分配、または `LcNmpc`）にする。

## 7. 実装事実 — 上流の type 切替との関係

PyMPC は `mpc_params['type']` で nominal / sampling / lyapunov を切る。それは **短い SRBD-MPC 同士** の比較である。  
この手順では、その前に **割り算対 LC NMPC**（フェーズ 1）と **割り算対 acados**（フェーズ 2）を置く。割り算に勝てない予測は、足踏み以前の問題を抱えている。  
sampling / lyapunov は、nominal と割り算の表が1枚できたあとの別実験である。[12](12_Block_Performance_Comparison.md) §4。
