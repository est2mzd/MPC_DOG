# 難易度マップ — 3軸と、混ぜてよい順番

進める順番の正本は [00](00_README.md) である。本章は **フェーズ 3** で、どの軸を同時に動かしてよいかである。フェーズ 0–2 が終わってから使う。

## 1. 結論

難易度は一本道ではない。次の3軸である。**一度に動かす軸は1つ。**

```text
軸L  移動の複雑さ     静止 → 足踏み → 遅い歩き → 速く → 加速・旋回
軸G  ゲイト           full_stance → crawl → trot → pace → bound
軸T  地形             平地 → 滑らか坂 → 低い凸 → 欠け → （最後）凸凹坂
```

4本目に **軸C 制御の中身** がある。ここが性能比較の軸である。予測最適化は軸C の値であり、軸そのものではない。

```text
軸C  脚力を決める     EqualShare → FxShare → LcNmpc → GrfMpc nominal → sampling / lyapunov
     トルクにする     MapJT → WeightedWbc     （別関数。脚力と同時に切らない）
```

比較するときだけ動かす。地形や速さと同時に切らない。EqualShare は軸C から消さない。詳細は[12](12_Block_Performance_Comparison.md)。

## 2. 全体図（方針）

フェーズ 0–2 で関数を厚くし、フェーズ 3 で軸 L / T を上げる。

```text
フェーズ 0
  S0  Plant
  S1  平地静止          EqualShare + MapJT
  S2  高さ
  S3  その場足踏み       PeriodicGait + Swing
  S4  ゲイト種類         パラメータのみ          ← 軸G の入口
  ごく遅い前進           vx 小。着地は今の xy

フェーズ 1  LC            KF、2点参照、NMPC、WBC、ハイブリッド
                          （軸C の LcNmpc と WeightedWbc。EqualShare と MapJT は残す）

フェーズ 2  PyMPC         着地点先送り、地形、acados
                          （軸L の歩行入口の本採用。軸C の GrfMpc）

フェーズ 3
        ├─ V0–V7  速さ（flat 固定）            ← 軸L を上げる
        ├─ Ts1–Ts5 坂（v 遅く固定）            ← 軸T の坂
        ├─ Tb1–Tb4 凸（v 遅く、勾配0）         ← 軸T の凸
        └─ Th1–Th5 欠け（v 遅く、勾配0）       ← 軸T の欠け
                │
                X1  中速 × 平地（V の勝ち）
                X2  遅い × 坂+低い凸
                X3  遅い × 欠け+平地（ずらし ON）
                X4  5 kph × 凸凹坂             ← 教材デモ相当。最後
```

X4 を足踏みの次に置かない。フェーズ 1 のうちに V や T に入らない。

## 3. 混ぜてはいけない組（方針）

| 同時に変える | 倒れたとき分からないこと |
|---|---|
| \(v\) と \(\alpha\) | 可動域か重力分か |
| \(v\) と欠けずらし | 時間切れか欠けか |
| bound と坂 | ピッチがゲイトか斜面か |
| EqualShare→予測 切替と perlin | 力か地形か |
| step_height と予測の重み | 遊脚かコストか |
| 推定 KF と凸 | \(x_0\) か床か |
| NMPC と WBC を同じ週に初投入 | 脚力かトルクか |

「一段に現象一つ」はフェーズ 0 だけでなく V/T/X でも同じ規則である。[01](01_One_Difficulty.md)。

## 4. ある程度の高速・欠け・凸凹・坂 — 分解の要約

欲しい完成形は、次の **原子** に落ちる。原子を飛ばして完成形を解かない。

### 高速（軸L）

1. ごく遅い直進（フェーズ 0。着地は今の xy）
2. 先送り付きの遅い直進（フェーズ 2 のあと V0）
3. \(v\) だけ上げる（V1）
4. \(L_{stance}\) を見る（V2）
5. \(f\) を上げる（V3）
6. 加速だけ（V5）
7. 平地 5 kph（V7）

詳細 [08](08_Speed_Ladder.md)。

### 地面の欠け（軸T）

1. blind で落ちるのを見る（Th1）
2. \(\mathcal S_{terrain}\) へずらす（Th2）
3. 届くか（Th3–Th4）
4. 止まる（Th5）

詳細 [09](09_Holes_and_Bumps.md)。

### 凸凹（軸T）

1. 低い一段、step_height（Tb1）
2. 着地 z（Tb2）
3. perlin / bumpy_flat（Tb3）
4. boxes（Tb4）

### 上り下り（軸T）

1. 斜面静止（Ts1）— ここで水平力の必要を見る
2. 斜面足踏み（Ts3）
3. 遅い上り（Ts4）と遅い下り（Ts5）を別実験
4. 推定角（Ts6）

詳細 [10](10_Slopes.md)。

### 最後に混ぜる

教材の **5 kph × 凸凹坂** は原子ではない。V7 と Tb3 と Ts4/Ts5 がそれぞれ成立してから X4 にする。

## 5. 実装事実 — 上流・教材との位置づけ

| 完成形 | この手順での位置 |
|---|---|
| PyMPC 標準 `run_simulation`（perlin、trot、最初から MPC） | 原子が全部 ON。学習の入口にしない |
| 教材の平坦スモーク | およそフェーズ 2 の遅い前進（acados あり） |
| 教材の boxes / perlin | Tb4 / Tb3。速さは教材次第 |
| 教材の 5 kph × bumpy 坂 | X4 |
| LC 実機ループ | フェーズ 1 相当が全部 ON。学習では一つずつ足す |

## 6. 関数に分けることとの一文

難しい問題を小さくする、とはシーンを易しくすることだけではない。  
**同じ1周期の呼び出しに対して、中身を足す順序を決めること** である。

速さは \(v\) と \(f,d\) と \(F_x\)。  
坂は床の傾きと摩擦の法線。  
凸は swing の z。  
欠けは着地点の安全集合。  
予測最適化はそれらのあとで、同じ `Grf` を出す **比較対象** である。割り算実装は残したまま足す。[12](12_Block_Performance_Comparison.md)。
