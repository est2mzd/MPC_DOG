# 地面の欠けと凸凹 — 地形軸（速さは遅く固定）

進める順番の正本は [00](00_README.md) である。本章は **フェーズ 3** の地形のうち、欠けと凸凹である。着地点の先送り（フェーズ 2）が動いてから始める。

## 1. 結論

欠けと凸凹は **速さ梯子の続きではない。** 遅い平地歩行（V0）の上に、地形の現象を一つ足す。  
コントローラ系統は増えない。触るのは着地点、`SwingPath` の高さ、任意で高さ地図である。

3集合の理論: [qpympc-study/13](../qpympc-study/13_Feasibility_on_Rough_Terrain.md)。  
標準 PyMPC は `blind` で交差を取らない（実装事実）。自分の梯子では、交差を **段階的に電源を入れる**。

## 2. 欠けと凸凹は別現象（方針）

| | 地面の欠け | 凸凹・段差 |
|---|---|---|
| 失敗の見え方 | 足が空中または底。支持を失う | 足が予定より早く当たる / 届かない |
| 必要な集合 | \(\mathcal S_{terrain}\)（乗ってよい点） | 主に z と `step_height` |
| 先に足すもの | 着地点ずらし | 遊脚の上げ幅、足先 z 参照 |
| 同じにしてはいけない理由 | 「避けた点」へ **時間内に届くか** が別問題 | 高さ追従であり、xy 回避ではない |

一段で「random_boxes + 欠け + perlin」を置かない。

## 3. 凸凹の段（T凸）

速さは V0（遅い）。ゲイトは trot。脚力はフェーズ 2 までで選んだもの（通常 `GrfMpc`）を固定。

| ID | 新しい現象 | 触るブロック | まだやらない |
|---|---|---|---|
| **Tb0** | 平地（対照） | なし。ログの型を合わせる | — |
| **Tb1** | 低い一本の段（既知） | `SwingPath` の `step_height` を段より大きく | 足場 xy を変えない |
| **Tb2** | 段の上に乗る | 着地 z を床高さへ。`FootPlacement.z` | 地図探索 |
| **Tb3** | 連続した低い起伏 | `Plant` の scene を perlin / bumpy_flat に | 速度を上げない |
| **Tb4** | ランダム箱 | scene `random_boxes` | 欠け扱い、高速 |
| **Tb5** | 地形平面の推定 | `TerrainPlane`（PyMPC `TerrainEstimator` の考え方） | VFA 非公開依存 |
| **Tb6** | 高さ地図で着地 z | HeightMap 相当。標準 PyMPC は非 blind のみ | virall VFA |

**実装事実:** ワークショップは `flat` / `random_boxes` / `perlin` と、追加の `bumpy_*` を持つ。標準 PyMPC `config` の scene 既定は `perlin`。学習では Tb0 を明示的に `flat` にする。

**推測:** Tb1 で step_height だけ上げて落ちるなら、問題は MPC ではなく遊脚軌道である。

## 4. 地面の欠けの段（T欠け）

一本の既知の欠け（幅と位置がログに書けるもの）から始める。速さは V0。

理論（13 章）:

\[
p_{td}\in
\mathcal S_{terrain}
\cap
\mathcal R_{kinematic}
\cap
\mathcal R_{timing}
\]

標準コードにこの交差関数は無い（実装事実）。自分で足すなら一段ずつである。

| ID | 新しい現象 | 触るブロック | まだやらない |
|---|---|---|---|
| **Th0** | 欠けなし対照 | — | — |
| **Th1** | 欠けの上を **blind** で踏む | 何も足さない。失敗を見る | 回避を足さない（観察段） |
| **Th2** | 乗ってよい点へ xy をずらす | `FootPlacement` が \(\mathcal S_{terrain}\) を見る | 運動学・時間はまだ見ない |
| **Th3** | ずらした結果、IK 不能 | \(\mathcal R_{kinematic}\)。届かなければずらす量を小さく | 速度変更 |
| **Th4** | 時間内に届かない | \(\mathcal R_{timing}\)。\(v^{ref}\) を落とすか \(f\) を上げる | ゲイト種類の変更 |
| **Th5** | それでも無い | `SafetyGate` で止まる | 「賢く跳ぶ」新制御 |
| **Th6** | 地図が未知 | センサ / HeightMap。推定の話 | 高速 |

13 章の対応順（安全点 → 減速 → \(f\) → duty → 位相 → ゲイト変更 → 停止）を、**Th2→Th4→Th5** に割り当てる。一気に全部の if を書かない。

## 5. 着地点関数は同じ。引数が増えるだけ

```text
footholds = placement.suggest(cmd, hips, lift_off, stance_time, terrain_query=None)
```

- 凸では `terrain_query` が z（と任意で平面）
- 欠けでは `terrain_query` が「この xy は乗ってよいか」
- どちらも着地点関数の引数が増えるだけである
- 脚力（`GrfMpc` 等）の入力は従来どおり着地点と接地スケジュール

欠け用に別の予測器を立てない（方針）。先に着地点が安全点を出し、予測はそこへ寄せる。  
着地点が欠けを出したままコストで避けさせる、は後の実験（推測: 短いホライズンでは間に合わないことが多い）。

## 6. 比較（同じログ）

| 実験 | 固定 | 変える |
|---|---|---|
| 凸の高さ | V0、trot、同じ脚力 | 段差 h |
| 欠けずらし | V0、同じ欠け | Th1 blind vs Th2 ずらし |
| 脚力 | 同じ Tb3 | EqualShare vs GrfMpc（凸では割り算が苦しい予想） |

EqualShare は水平力も姿勢も見ないので、凸で落ちても「予測が必要」の観察になる。欠けの Th1 は脚力以前に着地点の問題である。

## 7. 確認質問

- 欠けで落ちたのは \(F\) 不足か、足が落ちたか（着地点ログ）
- ずらした点は、残り swing 時間で届くか
- 凸で上げたのは `step_height` か、予測の \(Q\) か（前者から）
- 速さを同時に上げていないか
