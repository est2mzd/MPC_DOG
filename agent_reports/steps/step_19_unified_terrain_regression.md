# 同一プログラムによる地形回帰

## 第1章 概要

- Step 19 の地形回帰は、一つの実行ファイルと一つの yaml を使い、world だけを平地、渡れる穴、停止対象の穴、階段へ変更する
- 共通設定は、複数歩計画による停止要求を有効にし、足場の直接適用を無効にする
- 新しい足先支持、厳密な逆運動学、振り経路の判定は `shadow` にし、回帰中の制御出力を変えない
- 第1試行の平地は、胴体が x=-0.04 m から x=4.63 m まで進み、直立したまま終了したため成功である
- 第2試行の 0.30 m 穴は、胴体が x=-0.01 m から x=8.11 m まで進み、複数の穴を越えて直立したまま終了したため成功である
- 第2試行の影判定は、現在の成功足場にも `support=0` と `ik_exact=0` を記録したので、新しい判定をまだ強制しない
- 第3試行の 1.00 m 溝は、複数歩計画が減速後に停止をラッチし、胴体が溝の手前で直立したため成功である
- 第4試行の日本家屋の階段は、胴体が最初の蹴上へ届く前の x=2.77 m で傾き、転倒したため失敗である
- 第4試行は、失敗後も長い速度指令を継続したため、試験時間と記録量を不要に増やした
- 第5試行の連続穴は、15 cmの足場と15 cmの穴を5組越え、胴体が x=7.74 m で直立したため成功である
- 階段スクリプトはソース側のフィルタを一時変更したが、Release overlay はインストール済みフィルタを読んだため、一時変更を実行へ反映しなかった
- 第6試行は、共通平滑法線半径だけを 0.40 m から 0.10 m へ変更し、最大 x を 2.77 m から 3.07 m へ進めたが、最初の段で転倒した
- 次の変更は、地形経路から求めた振り足頂点を、実際の振り足軌道へ適用する

## 第2章 共通プログラムと共通設定

### 概要

- `run_quadsdk_unified.sh` は、同じ install overlay と同じインストール済み yaml を全地形で使う
- `multistep_planner.enabled` と `apply_stop_request` は真にし、`apply_foothold` は偽にする
- 足先支持、厳密な逆運動学、振り経路は `shadow` にする
- 各試行は、world、初期位置、継続時間、速度、記録名だけを変更する

### 詳細

- `run_quadsdk_unified.sh` は、同じ install overlay と同じインストール済み yaml を全地形で使う
  - 起動時は `ros2 pkg prefix local_planner` から試験対象の install を確認する
  - 起動時は共通設定が一致しなければ試行を開始しない
- `multistep_planner.enabled` と `apply_stop_request` は真にし、`apply_foothold` は偽にする
  - 複数歩計画は、到達可能な穴の先に足場列を作れる場合は停止を要求しない
  - 複数歩計画は、足場列が途切れる場合は減速または停止を要求する
  - `apply_foothold` は既存の足場位置を直接変更しない
- 足先支持、厳密な逆運動学、振り経路は `shadow` にする
  - `foothold_support_check_mode` は `shadow` である
  - `foothold_ik_check_mode` は `shadow` である
  - `swing_terrain_check_mode` は `shadow` である
- 各試行は、world、初期位置、継続時間、速度、記録名だけを変更する
  - 平地は `flat_wide` を使う
  - 渡れる穴は `flat_gaps_2m` の 0.30 m 穴を使う
  - 停止対象の穴は `flat_trench_s09_100` の 1.00 m 溝を使う
  - 階段は `jp_stair_10` を使う

## 結論

- 同一プログラムの第1試行は、平地を直進して直立したまま終了したため成功である
- 共通設定は、平地歩行を停止させず、既存のクロール歩行を維持した
- 同一プログラムの第2試行は、0.30 m の穴を複数越えて直立したまま終了したため成功である
- 新しい足先支持と厳密な逆運動学は、成功した穴越えの足場にも不成立を記録したため、現在のまま制御へ強制しない
- 同一プログラムの第3試行は、1.00 m の溝を渡れないと判定し、ロボットを直立したまま手前に停止させたため成功である
- 平地、渡れる穴、渡れない穴の三つは、同じ実行ファイルと同じ yaml で期待した動作を示した
- 同一プログラムの第4試行は、最初の蹴上へ届く前に転倒したため失敗である
- 階段失敗は長時間試験の末尾だけを調べず、最初の蹴上までの接近区間へ評価範囲を絞る必要がある
- 同一プログラムの第5試行は、連続する5組の穴を越えて直立したまま終了したため成功である
- 共通回帰は、連続穴を独立した成功条件として維持する
- 階段別の一時フィルタ変更はRelease overlayへ反映されず、同一プログラムの条件にも合わないため削除した
- 共通平滑法線半径 0.10 m は最初の蹴上への到達を改善したが、最初の踏面へ足を運ぶ区間の転倒を解消しなかった
- 次の技術的な積み上げは、地形経路から求めた振り足頂点を実際の軌道へ適用することである
